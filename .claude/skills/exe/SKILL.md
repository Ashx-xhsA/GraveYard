# 技能:/exe —— 照已批准的计划落地

前置:用户已用 `/make-plan` 出过计划、看懂并**批准**。本技能负责把它变成代码。

也可以直接执行 `docs/TODO.md` 里某条明确的小任务(一两行的改动本来就不需要写计划)——这种情况跳过第 1 步,直接从第 2 步开始。

## 步骤

### 1. 确认要执行哪份计划
- 列出/定位 `docs/plans/` 下对应的计划文档,读全文。
- 若有多份或不确定,先问用户是哪一份。
- **动手前确认用户已批准**;若他还想改,回到讨论,不要抢跑。

### 2. 分支
- 若计划的「分支建议」要求新建分支,或当前在 `main`:**先征得同意再** `git switch -c <名>`,名字用计划里给的。
- 已在合适分支就直接开始。
- ⚠️ `docs/prd-and-conventions` 这类文档分支**不要拿来装代码改动**,开始改代码前另开一个。

### 3. 逐步实现
- 严格按计划的编号步骤做,一步一步来,不跳步、不擅自扩大范围(计划「不做什么」里的别碰)。
- **面向初学者**:每步动手前用一两句大白话说"这步在干嘛、改哪个文件、为什么",做完简述结果。用户在学习,不要闷头写完一大堆。
- 遇到计划没预料的情况,停下说明并给选项,不要自行改设计。
- 遇到与 PRD「决策记录 D1–D11」冲突的情况,**停下来问**,不要自己改决策。

**本项目不做 TDD**(目标是快速上线,`client/` 和 `server/` 都没有测试框架)。取而代之,每完成一个有意义的步骤就跑一次下面第 4 步的检查,**不要攒到最后一起验**——没有测试兜底时,早发现比什么都重要。

### 4. 验证(替代测试的安全网)

每步做完、以及全部做完时:

```bash
npm --prefix client run lint     # eslint
npm --prefix client run build    # tsc -b + vite build ← 真正的安全网
npm run dev                      # 前后端一起起,在浏览器里实际点一遍
```

- **`tsc -b` 是这个项目唯一能自动抓住字段重命名漏改的东西**。改了数据模型字段名之后,必须跑 build,并把它报出来的每一处都改掉。
- ⚠️ 若组件里还大量是 `any`(TODO #13 的 `client/src/types.ts` 还没落地),`tsc -b` **抓不到字段名错误**。这种情况要如实告诉用户"这次改动没有自动检查兜底,只能靠手点",并建议尽快做 #13。
- 按计划的「验收标准」逐条核对,**在浏览器里真的点一遍**,不要只看构建通过就说完成。
- ⚠️ **碰了静态资源文件名的话**:macOS 大小写不敏感,本地一切正常不代表线上正常。提醒用户部署后复验 404。
- ⚠️ **碰了数据模型的话**:线上有真实数据,确认迁移脚本跑过或已明确要清库重 seed。
- 如实报告结果;失败就贴输出、定位、修,修完重跑,别跳过。

### 5. 收尾(遵守 CLAUDE.md)

- **必做**:在 `docs/claude/` 追加本次会话记录(模板见 `docs/claude/README.md`:背景/改动清单/决策与理由/验证/发现待办)。命名 `YYYY-MM-DD_<branch或主题>_会话记录.md`,同一天同一 branch 追加到同一文件。
- **必做**:更新 `docs/PROGRESS.md`(唯一的进度来源):刷新「当前阶段 / 上次做完 / 👉 下一步起点 / 卡住 / 当前分支」。保持极短,只写现在的状态。若本阶段全部做完,把「当前阶段」推进到 `docs/ROADMAP.md` 里的下一个 Phase。
- **必做**:在 `docs/TODO.md` 里标掉做完的条目。**别重排编号**——ROADMAP 和 PROGRESS 都按编号引用。
- 若做了与 `docs/PRD.md`「决策记录」现有条目相反或对其修订的重要决策,**回写 PRD** 加一条 `Dn` 并注明日期与理由;数据结构变了同时回写 `docs/DATA-MODEL.md`。
- 若本次决策与 `docs/ROADMAP.md` 的阶段顺序/划分/优先级冲突,**回写 ROADMAP** 的「变更记录」表并注明日期与理由。
- 过程中发现但没处理的问题,够格的加进 `docs/TODO.md`(给新编号),只是观察就留在会话记录里。

### 6. 向用户总结

做了什么、验证结果(如实,失败也说)、待办或需他决定的点。

**提交/推送由用户决定,不主动 commit/push。** 文档改动和代码改动建议分开提交。
